# 插件宿主领域服务协议

适用于插件领域服务层，叠加 [宿主架构协议](<plugin.host.md>)。

## 定义与导出

- 领域服务统一使用 `defineService`，不创建第二套服务宏或以裸对象替代。
- 一个服务模块只导出服务对象，导出名为文件名的驼峰形式；不使用冗余 Service、Manager 后缀。
- 服务对象成员全部为函数。Map、Set、AbortController、写队列、锁和在途任务放模块私有作用域，不暴露可变状态。
- 模块专属公开类型放同目录 `<module>.types.ts`，跨模块共享类型放 `types/`；内部类型、常量与函数保持私有。
- 不为私有函数添加分隔注释或仅用于测试的导出；单模块常量直接定义在消费模块内。

## 领域职责与方法

- 一个模块对应明确领域。具有独立生命周期的职责可以独立服务，不按机械单消费者规则强行合并。
- 使用一致的领域动作动词，持久化、长任务、只读查询和编排分别表达真实语义；不为凑齐命名增加未使用的方法。
- 只读方法不创建、认领、恢复资源，不落盘、不推进任务，也不猜测缺失数据；写操作走明确入口。
- 不为一次模型调用创建薄服务，也不把所有领域塞进一个服务；边界优先于行数和文件数。

## 宿主能力与签名

- 参数直接表达业务需求，不包装无意义的单对象，不透传全局 deps、ctx 或 host。
- 基于 dsh-h3 的服务使用原生 `getServerContext<Context>(server)` 获取当前激活实例的宿主能力，不自建绑定、清除或泛型兼容层。
- HTTP 服务通过宿主入口的 `ctx.effect` 激活；安全中间件和官方事件注册可以使用其作用域 Context，但不能将其透传为业务依赖对象。
- 依赖官方公开能力与真实归属校验，不凭名称或标识符格式认领宿主资源。

## 数据写入

- SQL 归数据库模型，数据库单例运行时导入；服务负责校验、编排和模型调用。
- 文件配置通过既有存储入口串行合并、校验后原子落盘，不擅自改变持久化介质。
- 凭据与数据库存在跨存储边界时明确提交顺序、失败回滚与一致性快照，不能读到交叉版本。
- 应持久化的业务状态不能仅存内存；资源结束、归档与进程重启遵循明确的数据保留语义。

## 调度与生命周期

- 周期工作复用 runtime 调度基础设施，由运行服务组装与撤销；不重复创建 timer，不擅自创建操作系统计划任务。
- 缺失、未配置或主动关闭的能力安静跳过，不当作执行失败消耗重试次数或持续输出失败日志。
- 初始化完整成功后才注册或写回；坏 JSON 与 I/O 错误不能静默转为空配置。
- 私有任务状态机有明确终态、超时与并发规则，卸载取消资源并 await 结束，不遗留孤儿进程或悬空 Promise。
- 已经成功提交的保存不能仅因随后取消而报告失败；可取消阶段与不可取消提交阶段保持一致语义。

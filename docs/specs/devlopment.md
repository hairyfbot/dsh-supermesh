# 通用开发协议

适用于所有代码。领域约束通过 [AGENTS.md](<../../AGENTS.md>) 路由叠加；用户明确指定的架构、组件拆分和交互不受通用精简建议覆盖。

## 状态与边界

- 数据只保留一个权威来源，写操作单点收口，读操作只读或订阅。派生值按需计算，不复制成独立业务状态。
- 表单草稿、折叠状态和请求生命周期具有独立语义，可以保存在组件中；不得将完整服务数据镜像为另一份可写真值。
- 文件、数据库、会话投影和客户端 Store 各自明确所有权。使用官方投影读取宿主事实，不自行折叠日志复制官方状态机。
- 完整 Hydration 成功后才允许写回。初始化失败必须暴露，不能吞掉错误后用空状态覆盖持久化数据。

## 组件与抽象

- 页面、图表、筛选器、图节点、表单区块等按界面职责抽离，保留有助阅读与维护的组件边界。
- 单一消费者不是合并 UI 组件的理由。禁止把整个页面及其图表、布局计算、子面板强行塞进一个文件。
- 删除没有业务价值的纯转发、改名别名和重复封装；不得为了消除一层调用而破坏领域、协议或资源生命周期边界。
- 独立业务流程各自管理状态和请求，不为复用外观而把不同流程的状态、校验和请求混入通用 Hook 或组件。
- 清除废弃代码、无用导出、兼容存根与无消费者的常量。移动已跟踪文件优先使用 `git mv`，不保留过渡转发文件。
- 避免防御性编程：校验真实边界和已知风险，不添加猜测性回退、泛化兼容层、无依据重试或吞错默认值。

## 目录归属

| 内容 | 归属 |
| --- | --- |
| 既有页面与页面子组件 | 对应 `src/client/pages/<领域>/` 及其 `components/` |
| 插槽业务 UI | `src/client/ui/<领域>/` |
| 无业务语义的共享展示组件 | `components/` |
| 可复用组件状态与上下文访问 | `hooks/` |
| 单 Store 专属逻辑与初始状态 | 对应 Store 模块 |
| 宿主领域编排 | `src/service/` |
| SQL 查询和数据库写入 | `src/database/models/` |
| 跨模块共享纯计算 | `utils/`；不得放有状态调度器或领域预设组装 |
| 模块专属类型 | 同目录同名的 `<module>.types.ts` |
| 跨模块共享类型 | `types/` |

目录整理不能作为重写 UI、合并全部页面或改变工具归属的理由。

## 副作用与通信

- 优先使用声明式请求、状态与订阅 Hook。
- 原生 Effect 只用于显式注册和释放外部资源，例如事件订阅、会话 retain 引用和网络取消；必须标注 `// keep:effect <原因>`。
- 每个订阅、子进程、注册回调和异步操作均有明确释放方；卸载时取消并等待必要的收尾，不遗留后台工作。
- Origin 和 owner 校验在 HTTP 入口统一完成；资源、角色、项目及线程权限仍由对应领域边界校验，不能用入口鉴权替代业务授权。
- 客户端先归一化可检查的输入，宿主验证可信边界。可预判的平台限制在发起请求前提示，网络和进程失败仍须如实处理。
- 谁执行操作，谁负责结果提示；不得多层重复 Toast 或将失败显示为成功。

## 文档与验证

- 规范以直接、可执行的现行条款表达，不写历史叙述、迁移流水或相互冲突的附加规则。
- 代码以表达清楚为先，默认零注释；必要的资源 Effect 标记与真实故障原因说明保留。
- 接口、类型与实现同步，生成代码通过生成器更新。
- 按 [测试与验证协议](<testing.md>) 验证；禁止未经用户允许执行构建。不得用测试约束倒逼业务迁就错误夹具。

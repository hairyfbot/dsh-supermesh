# 插件客户端协议

适用于插件客户端入口、页面、组件、状态与官方 UI 扩展。叠加 [通用开发协议](<devlopment.md>)。

## 装配与依赖

- 客户端入口直接注册 locale、Store、官方插槽与事件定义，仅承担装配。
- 插槽和事件注册直接在入口声明，不建立只转移注册代码的 register/install 中间层。
- 页面和组件承载 UI 与交互；入口不维护业务状态、不执行业务请求、不实现业务组件 JSX。
- 业务直接调用 GenAPI 生成的接口函数，不手写 fetch 包装，不建立改名转发 API，不手改生成文件。
- 模块直接引用实际定义文件；禁止纯转发 barrel 和兼容 re-export，不形成页面、Store 与入口之间的循环依赖。

## 组件边界与目录

- 保留 `pages/<领域>/page.tsx` 与 `components/` 的合理拆分。图表、布局计算、筛选器、表单和详情区块按职责抽离。
- 单一消费者不是合并 UI 组件的理由。代码整理保持原 DOM、布局、交互与清晰的组件边界。
- 插槽业务组件放在 `ui/<领域>/<职责>.tsx`，导出名按组件职责命名；不在客户端根目录堆放业务组件。
- 多分支页面以 `Switch` + `Case` 分发到各自组件，独立流程各自管理状态、请求、校验和交互。
- 共享纯展示结构，不将不同流程的请求、身份、配置与授权状态混进通用表单或登录组件。

## 注入与状态

- `ctx` 和 `t` 通过入口 Provider 注入，组件使用上下文与翻译 Hook 获取，不经 props 穿透。
- props 只传所需业务数据、事件参数或官方插槽数据，不透传整个宿主能力对象。
- Store 和服务响应保持唯一来源，不把同一业务集合复制到多个可写 Store 字段；派生展示按需计算。
- 使用真实宿主导航与公开 API，按实际能力启用按钮，不能用空处理函数或永久 disabled 替代实现。错误必须可见。
- 请求支持取消与过期响应隔离，销毁或切换上下文后不得让旧请求更新当前内容。

## UI/UX 与样式

- 用户指定的设计稿、图片或原版源码是界面权威，参考源码只读。不得自行重设计、近似替换或扩大授权差异。
- 保持布局、尺寸、间距、字体、颜色、顺序、控件位置、响应式规则与交互；把真实逻辑接入指定结构。
- 展示真实状态，不伪造示例账号、事件、运行状态或统计数字。
- 样式使用 Tailwind 与官方主题变量，不为业务组件创建 CSS Module、配套样式声明或动态 style 标签。
- 官方界面扩展使用公开插槽、消息协议与组件语义；不得用 DOM 查询、手工插入、假 testid 或官方哈希类名伪装接入。
- 空内容使用符合场景的共享组件，保留既定布局；零值与加载失败分别表达，不能用空状态掩盖错误或伪造非零数据。

### 3.2 数据请求与查询 (`TanStack Query`)

* QueryClient 单例定义在 `src/client/client.ts`，由入口以 `QueryClientProvider` 提供；插槽组件在面板外渲染时各自补 Provider。
* 页面数据归页面所有。服务响应只经 `useQuery` 持有，**不复制进 Store**；Store 仅存放导航、筛选、表单草稿等通用 UI 状态。
* 查询定义在 `src/client/queries/<资源>.ts`，key 集中在 `queries/keys.ts`；组件按需调用自己的 hook，不预取其他组件的数据。
* 列表项等重复渲染的组件由容器统一调用 hook，经 props 下发旁路数据，禁止每行各自发请求。
* 操作型使用 `useMutation` 管理；需要完成后刷新数据时在 `onSettled` 里 `invalidateQueries`，不写 `onSuccess` 手工改缓存或回填 Store。
* 实时数据按需设置 `refetchInterval`；加载与失败分别用 `isLoading` / `error` 表达，不能用空状态掩盖错误。
* 全局刷新由布局刷新按钮调用 `client.invalidateQueries()` 完成，不额外维护刷新状态机。

## 官方 API 与生命周期

- 使用当前安装版本的公开类型和实现核实 slot name、owner、props、事件与消息来源，不用 any、私有组件导入或兼容存根掩盖版本差异。
- 自有消息使用明确的自有来源，匹配和独占范围限于本插件；不冒用用户或官方来源，不覆盖其他插件与全局节点处理。
- 使用官方提示词扩展或上下文注入能力，不覆盖官方提示词组装过程。
- 宿主提供的模块保持正确 external 和 manifest 注入，浏览器安全依赖按加载器要求打包。
- 插槽通过 `ctx.slots.inject` 与 `ctx.slots.register` 管理，注册、订阅、retain 引用和请求均在所属生命周期内释放。
- 插件开发不执行未经授权的构建、不启动替代服务；验证标准遵循 [测试协议](<testing.md>)，不把组件夹具称为真实应用验证。
